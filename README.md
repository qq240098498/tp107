# tp107 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5107>

端口固定为 `5107`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条、落在多少处，并按级别、按规则、按文件分别汇总；命中可以按条看，也可以按处看，单条命中还能标记忽略或恢复
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 合并口径（按条与按处）

- 按条：一条规则在一个文件的一行上抓到一次记一条，总数就是条数
- 按处：同一文件同一行只算一处，一处里被几条规则抓到就记几条；页面上按条看、按处看两个视图可以随时切换
- 按处汇总时列出这一处参与抓到的规则编码与级别；一处里级别不一致时，这一处整体按有效条目里最重的一级对待（错误 > 警告 > 提示），依据就写在这一处的级别旁边
- 忽略按同一套口径处理：一处里部分条目被忽略时，这一处显示还剩几条有效（有效 x / 共 n 条）；整处都忽略时按全部条目取最重一级定级，并标注整处忽略
- 两套数字互相印证：按条的总条数等于各处条数加起来的合计，有效与忽略两边也分别对得上，概要里会把两头的数并排摆出来核对
- 概要里写明这一轮同一处最多同时被几条规则抓到，以及是哪几处

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "ignores": [...] }`，其中 `ignores` 记录被忽略的命中（规则、文件、行号、操作者与时间）。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。规则或文件被删除后，引用它们的忽略记录会在下次载入时一并清掉。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单、按处汇总与两套总账 |
| POST   | /api/hits/ignore  | 按（规则、文件、行号）忽略一条命中，可带操作者   |
| POST   | /api/hits/unignore | 按（规则、文件、行号）恢复一条被忽略的命中      |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
