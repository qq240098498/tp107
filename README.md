# tp107 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

```

├── server/

├── .gitignore

```

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5107>

端口固定为 `5107`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数，并同时给出**按条**与**按处**两套汇总数字：
   - 按条：一条规则在一个文件的一行上的一次命中算一条；按处：同一文件同一行，不管被几条规则抓到，只算一处
   - 两套数字同时显示并互相印证：条总数等于各处条数之和，有效条、已忽略条分别也等于各处对应数字之和，页面上逐项打勾，对不上会直接标红
   - 每处列出参与抓到的规则编码与级别；一处里各规则级别不一致时，这处整体按其中**最高级别**对待，并写明依据是哪一条（或哪几条）规则；同时给出剔除忽略条目后的有效级别
   - 概要里写清这一轮一处最多被几条规则同时抓到、出现在哪里，以及“被 1/2/3… 条规则抓到的处各有多少”
   - 命中清单可在“按条看 / 按处看”之间切换；每条命中都能登记忽略或取消忽略
4. “已忽略的命中”区列出全部忽略登记：规则编码、级别、文件、行号、那一行内容、原因、操作者与时间，可随时取消；忽略的粒度永远是“某条规则在某个文件某一行上的一条命中”
5. 一处里只有部分条目被忽略时，这处仍然保留，概要与列表都写清总共几条、其中几条已忽略、还剩几条有效、有效部分按哪一级对待；整处条目都被忽略时，这处计入按处总数但不再计入有效处
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条；按处归并时以“文件 + 行号”为一处
- 处的整体级别取参与规则里的最高级别（错误 > 警告 > 提示），依据为达到该级别的全部规则编码；有效级别取剔除已忽略条目后的最高级别，整处都被忽略时没有有效级别
- 忽略只挂“规则 + 文件 + 行号”三元组：同一行上别的规则不受影响；规则被删除或文件被移出清单时，相关忽略记录一并清掉
- 同轮结果里两套总数必须勾稽：按条总数 = 各处条数之和；有效条数 = 各处剩余有效之和；已忽略条数 = 各处已忽略之和；按级别、按规则的分项计数也都与条总数对得上

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "ignores": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。载入时会对忽略记录做兜底整理：指向已删除规则/文件、行号越界或同一三元组重复的忽略一律丢弃。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单（相关忽略一并清掉）             |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中（按条）、处（按处）与两套对账汇总 |
| GET    | /api/ignores      | 忽略清单，带规则编码/级别、文件路径、行号、原因与操作者 |
| POST   | /api/ignores      | 登记忽略（ruleId + fileId + lineNo + reason + operator） |
| DELETE | /api/ignores/:id  | 取消一条忽略，相关命中下一轮重新计入           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
